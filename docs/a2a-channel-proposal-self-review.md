# 自评审：`-A2A` 频道方案

> 对象：`docs/a2a-channel-proposal.md`（2026-11-06 稿）
> 判据：**这份方案敢不敢被反驳**。下面的每一条都是对着源码复核过的，不是印象。

## 〇、结论先行

- **骨架与「道 / 一 / 二 / 三」一致**：方案落在频道层（`channels/` + CLI 参数），
  一行 `agent.py` / `runtime.py` / `llm.py` / `prompt.py` 都不动；
  A2A 只是「另一张嘴」，不改变 ReAct 循环，不往 system 里写任何字节。
- **缺陷集中在「边缘机制」层，不在核心假设**：核心假设（必须自己跑 HTTP server、
  必须走 `Runtime.run()`、必须按 ADP 注册）经得住；出问题的地方是
  注册生命周期、退出竞态、跨机器地址、以及两处我写在正文里但没写清的默认值。
- 写作过程中**当场改回文档 5 处**（本文件第五节），另外识别出 **1 处 P0 / 7 处 P1 / 6 处 P2**。
  2026-11-06 人类裁决「这就是个特殊的频道，不动内核」后，原「每 task 隔离会话」候选撤销
  （见第六节），方案的内核零改动由「自设判据」升级为**裁决**。
- **第二轮裁决（同日）**：`-A2A` 永远是开关、端口自动探测 9000–9999、卡片不签名。
  三条都落在频道层，**骨架不变**；新增的缺陷只有一条类型 ——
  「端口探测」与「`id` 由 URL 派生」天然对立。它由裁决接受，并用两条机制偿还
  （复用 `last_port` + 旧条目收尸，方案 §4 末），剩下的暴露写进 README（方案 §9）。
  本轮另抓出 **1 处 P1（Windows 上 `allow_reuse_address` 会让探测假成功）**
  与 1 处我自己的口径不一致（`last_port` 该在 bind 成功就写，与注册无关）。
- **第三轮裁决（同日）**：`--a2a-port` **指定了就用指定的**（方案 §5.4）。
  这一轮没有新增开关 —— `--a2a-port` 本来就在表里，被改的只是它的**性质**：
  从「候选序列的第一位」变成「另一种模式」（不探测、不读 `last_port`、不降级）。
  它同时补上了第二轮留下的一个缺口：自动模式只能「尽量不漂」，而**显式端口是让
  registry 里 `id` 跨重启不变的唯一手段**。新增 **1 处 P1（显式端口不得写成
  序列首项 + 降级）**，以及 1 处措辞级修正（advertise 与显式端口矛盾时是**报错**
  而不是警告 —— 显式模式下不存在漂移，只存在自相矛盾）。

## 一、设计哲学八问

| # | 问题 | 判断 |
|---|---|---|
| 1 | **道**：有没有把判断写进 if / 常量 / 关键词？ | 没有。频道里的分支全是**协议形状**（方法名、`role` 拼写、`blocking` 布尔、状态名），转述不是思考。唯一像「规则」的是 `[openthree] ` 前缀判定（§6.2），它判的是**内核自己的文案**，不是用户内容 —— 且它的真源是 `bridge.NOTICE_PREFIX` 一个常量，不是散落的字符串 |
| 2 | **一**：有没有绕过 `write_system_prompt` 往 system 里写？ | 没有。A2A 一行 system 都不加。相反方向是一致的：卡片的 `name` **每次现读** `identity.json`，模型改名 → 卡片跟着变 → registry 的 `changedAt` 记下这次漂移。「能改，也能看见自己改过什么」在这里同样成立 |
| 3 | **二**：有没有引入第二份拷贝？ | 有四处曾被引入，已逐条收敛：①配置真源是 `channels.yaml`，`-A2A` 只注入本进程且撞名**替换**；②默认值只住 `a2a.py` 常量，`_SPECS` 的 `Field` 只留 `hint`（`config.py:5-8` 明说不 import 实现）；③落盘文件只存 registry 侧凭据（agent_id/token/card_url），不复制配置；④失败/收工文案的前缀收敛成一个常量（§6.2） |
| 4 | **三**：有没有替模型规定先做什么？ | 没有。A2A 任务与控制台输入在模型眼里是同一件事（`compose_input`，`bridge.py:31-34`） |
| 5 | **万物**：让模型更容易自造，还是更难？ | 中性偏正：卡片跟随 `set_identity`；但**刻意不把自造 functions 的清单塞进卡片** —— 理由在 §3.2 第 4 条（卡片暴露接口，不暴露工具名）。这是一个「让它少暴露」的选择，需要在文档里说清是**有意的**，否则下一个人会当成遗漏来修 |
| 6 | **极简**：开关多了吗？ | 7 个参数偏多。能砍到 3 个（`-A2A` / `--a2a-registry` / `--a2a-no-register`），但端口冲突、跨机器注册、对面超时三个都是真实场景。**保留**，且 §5.1 每行都写明了"为什么它不能是常量"。**端口探测没有新增任何开关**：`--a2a-port` 从"默认 9100"变成"留空即自动"，候选序列 9000–9999 是模块常量而不是参数 —— 想固定就显式给一个值，不想管就别给。这是第二轮"能力变大、开关没变多"的改动。第三轮同样没加开关（`--a2a-port` 早就在表里），它砍的是一条**隐含路径**：显式端口不再参与候选序列，于是 a2a.py 里少一个"首项可能降级"的分支，也少一个"显式还是自动"的运行期布尔（`explicit is not None` 就够）；顺带拒掉 `OPENTHREE_A2A_PORT`（端口来源从 3 处回到 2 处） |
| 7 | **成本**：system 字节会不会从「随文件变」变成「随每步变」？ | **不会**。A2A 不改提示词、不改工具清单、不进上下文。唯一持续成本是 60 秒一次 `GET /v1/agents/{id}`（约百字节）。§10 的「内核不动」就是这条的守门人 |
| 8 | **诚实**：读数/承诺有没有夸大？ | 有 3 处曾经的夸大，已改：①「支持 A2A」→ 明确为「0.3 的 3 个方法 + 1.x 别名，无流式/推送/鉴权/持久化」；②`cancel` 不写成「支持取消」而写「不再等，不是停手」；③`blocking` 的默认值**不赌**（§3.3）。仍欠一条：**共享会话 = 调用方能通过提示读到本会话最近的对话**，这句必须原样进 README → P1 |

## 四、硬伤

### P0（实现出来是错的）

**P0-1：`-A2A` 与 `--only` 撞车时会静默丢掉 A2A 频道。**
`manager.build()` 用 `only` 过滤（`manager.py:90-92`），而 `-i` 路径正是这样把
`--only` 传下去的（`cli.py:531`）。于是 `openthree -A2A -i --only wx` 里
**用户显式要求的东西没有起来**，命令行上只有一行「已启动 1 个」。
- 判据：显式要求的能力静默不生效 = 错，不是风格问题。
- 改法：`-A2A` 与 `--only` 同时出现且 `--only` 不含 `a2a` → 直接报错并列出正确写法；
  注入的频道名固定为 `a2a`，不做「用户换名」的自由度。

### P1（答辩时站不住）

**P1-1 跨机器注册的地址陷阱**（已改入 §8.6）：registry 在 `10.0.0.5`、卡片地址是
`127.0.0.1` 时，对方抓的是**它自己**的回环。这是「可指定 registry 地址」这个需求
落地时第一个会踩的坑，原稿只写了 `--a2a-advertise` 参数，没写这个场景。

**P1-2 端口一漂，旧条目就留在 registry 里**（已改入 §4，并随第二轮裁决升级）：
`id` 是旧 URL 派生的，所以 `card_url` 变了就是**另一条记录**，而旧那条不会自己消失。
原稿只写了「存 `card_url` 并比对，免得拿旧 `id` 跳过注册」——那只解决「新地址没注册」。
第二轮裁决要**自动探测端口**，于是漂移从"用户手动改端口"变成"可能每次重启都发生"，
所以还必须有**收尸**：拿存下的旧 `id` + 旧 `manageToken` 发 `DELETE`，
且发之前先探活旧地址（有 HTTP 响应就说明那边有活实例，不能删）。
两条机制缺一条，这个裁决就是在给 registry 生产僵尸条目。

**P1-3 退出/异常文案会被记成一次成功任务**（已改入 §6.2）：`SHUTDOWN_NOTICE` 与
异常文案都走 `send_text`，A2A 侧若不区分就会把「服务正在退出」当答案写进
`completed` 的 artifact。修法给了三条（常量收敛、前缀判定、退出前置 failed）。

**P1-4 共享会话的泄露必须在 README 里明说**（改入 §9，并已随 2026-11-06 裁决定案）：
A2A 任务与控制台共用一个会话（`bridge.py:100-104` + `-d` 的 `begin_session`，`cli.py:702`），
所以**远端调用方可以通过提示让模型复述本会话里最近的对话**。人类裁决「这就是个特殊的
频道，不动内核」之后，隔离方案撤销 —— 泄露从「可选风险」变成**既成事实**：
这句话必须原样写进 README，默认只听回环不能顶替这句话。

**P1-5 `blocking` 的默认值不能猜**（已改入 §3.3；**结论已于 2026-11-09 被实测推翻**，
见文末「第四轮」）：原稿写「A2A 0.3 的 blocking 默认阻塞」，这是我的记忆而非核对过的
事实。当时改成只认显式 `true` —— 「两种读法下都安全」这句对**协议**成立，对**客户端**
不成立：对面根本不轮询时，回得早等于没有答案。

**P1-6 Windows 上 `allow_reuse_address` 会让端口探测永远"成功"**（已改入 §5.4）：
`http.server.HTTPServer` 默认 `allow_reuse_address = 1`（`SO_REUSEADDR`）。POSIX 上它只
绕开 `TIME_WAIT`；**Windows 上它允许 bind 一个正在被监听的端口**（要拒绝得用
`SO_EXCLUSIVEADDRUSE`）。后果不是"起不来"，而是**起得来但收不到任务**：两个进程都认为
自己在监听，流量随机分给其中一个。这条比探测本身更要紧 —— 自动探测把"端口冲突"从
一次明确的 `OSError` 变成一次静默的错误绑定，所以 a2a.py 必须显式
`allow_reuse_address = False`，并在测试里断言它（方案 §11-7）。
- 判据：一个"自动重试"的机制，其失败信号必须是可信的；否则重试只是把错误往后推。
- **我第一遍的修法是错的**：写成「必须显式 `allow_reuse_address = False`」——
  一刀切在 POSIX 上会让紧接着的重启撞 `TIME_WAIT`，于是重启就漂（而这正是第二轮裁决
  想避免的）。正确的是一行平台分支：
  `allow_reuse_address = not sys.platform.startswith("win")`。
  两个平台的 `SO_REUSEADDR` 语义**不一样**（POSIX 不允许多个 listening socket 同端口，
  Windows 允许抢占），所以这条不能靠"跨平台常量"糊过去，必须有注释说明为什么分支。

**P1-7 `last_port` 的写入时机被我写错过**（已当场改回方案 §4 末 / §5.4）：原稿写
「上次成功 bind **并注册**的端口」。可 `--a2a-no-register` 永远不注册，于是那个字段
永远为空 —— 调试模式下每次启动都从 9000 扫，端口照样漂。
- 判据：这个字段复用的是什么？（端口，不是注册状态）
- 改法：**bind 成功就写** `last_port`；`agent_id` / `manage_token` / `card_url`
  仍然只在注册成功后写。两者生命周期不同，不能共用一个成功条件。

**P1-8 显式端口不得写成「序列首项 + 降级」**（已改入 §5.4）：
「指定了就用指定的」在实现上有一个几乎必然踩的坑 —— 把显式端口放进候选列表的
第一位，循环里遇到 `EADDRINUSE` 就 `continue`。这样代码看起来支持了参数，行为却是
「指定了，但只要被占就换一个」：用户以为在 9000，registry 里注册的是 9001，
`id` 也变成了另一条。错误还极其安静（服务起来了、面板里有记录、任务能收）。
- 判据：**结构上不能存在那条路径**，而不是靠循环里的一个 `raise` 守着。
  测试用 `last_port=9001`（空闲）+ 显式 `9002`（被占）⇒ 必须抛错、不得起在 9001
  （方案 §11-7 ③）—— 这条断言的存在意义就是「证明降级路径不存在」。
- 另一处同类陷阱：只把 **CLI** 当显式，忘了 `channels.yaml` 的 `port`。
  两条启动路径上「显式」的答案必须一样（§5.4 的来源判据）。

## 六、裁决（已无待确认项）

### 第一轮（2026-11-06，人类）

**「这就是个特殊的频道，不动内核」** —— 由此撤销原第 1 条「每个 A2A task 是否独立会话」：

### 第二轮（2026-11-06，人类原话「是开关；最好自动探测9000~9999的可用端口，因为会有冲突；不需要签」）

| 裁决 | 我这边的落地 | 它换掉了什么（诚实记账） |

### 这一轮我的判断与裁决的关系

### 第四轮（2026-11-09）：实测推翻 P1-5 —— 「协议正确」不等于「有人看得见」

人类原话：「是否完整测试了，我发了个任务，一直执行中的状态」。

**现象**：面板（OACP 0.2.1）发一条任务，界面永远「执行中」。

**证据（不是推断）**：

| 事实 | 出处 |
|---|---|
| 任务在我们这边是 `completed`，比提交晚 5 秒，带 artifact | `tasks/get t-4935b348814a4006` |
| OACP 账本停在 `working`，`updatedAt == createdAt == syncedAt` | `GET /api/panel/tasks?limit=5` |
| 面板的静默刷新只重读它自己的 SQLite，不发 `GetTask` | `web/app.js:1124-1139` |
| `GetTask` 只在用户点「从智能体刷新」时发 | `tasks.py:123-137` + `api.py:324` |
| 服务端没有任务级的后台同步（只有 agent 探活） | 全仓 grep `synced_at` / `create_task` |
| 上一轮报告里的「7 秒后 completed」是**我自己**调的 refresh | 事件流：`submit` → `response(working)` → `refresh(working)@01:04:46` → `refresh(completed)@01:04:49` |

**判据被推翻的地方**：P1-5 说「只认显式 `true`，缺省一律不赌」。它把问题读成「协议的
默认值该怎么读」，而真正的问题是「**谁来取这个答案**」。对面不轮询时，回得早不是
「更安全的默认」，是把结论丢进一个没人读的地方 —— 任务 5 秒跑完，界面挂 10 分钟。

**改法**：缺省就等（有界 `block_wait`，默认 45 < OACP 的 60 秒超时）；显式
`blocking: false` 才立刻 ack；读不懂的值按「等」处理（赌错这一边只慢一点，赌错另
一边是对方永远看不到结果）。已改写进方案 §3.3。

**测试为什么没抓住它**：那条用例（`test_absent_blocking_returns_immediately`）断言的是
「`message/send` 立刻回 working」—— 期望值是照**我们自己的实现**写的，于是它守的不是
契约，是旧决定。真正的契约是「**不轮询的客户端能不能看见结论**」，现在由
`test_absent_blocking_waits_and_hands_the_answer_back` 守，并在真 OACP 上端到端复验
（一次 POST 2.9 秒 → `completed`，脚本 `.openthree/tmp/e2e_panel.py`）。

**留下的自省**：「按规范默认值来」是一种伪装成严谨的逃避 —— 它把「这个客户端会怎么
消费我的响应」挡在门外，而那个问题才是产品。

### 第五轮（2026-11-09）：接入回调 —— 换了通道，判据没换

**先看这次没有推翻的东西**：第四轮的结论是「答案必须到达对方手上」。接入回调**没有**
推翻它，而是把「怎么到达」多开了一条路：能登记回调的调用方，答案由我们**送**过去；
登记不了的，仍然靠响应**带**回去。所以 `_client_waits` 的缺省从 `True` 变成
`not push` —— 输入变了，判据没变。

### P1（答辩时站不住）

| # | 硬伤 | 判据 → 改法 |
|---|---|---|
| P1-9 | **「有回调」不等于「回调能到」**：我把缺省从「等」改成「不等」，等于把送达责任从「响应」整体挪给了回调。回调坏掉（路径写错、进程重启丢了 token、防火墙）时，用户看到的是**和上一轮一样的「永远执行中」**，只是原因从「我们不送」变成「送不到」 | 承认这是有意的取舍：协议里登记回调就是「我有能力收」的声明，等待反而是替对方做决定。兜底不是再加一条规则，而是**让它可诊断**：4xx 立刻放弃并记一条「拒收」、5xx/连不上用满预算后记「没送出去」，两句话都指出结论仍在 `tasks/get`。想稳妥的调用方写 `blocking: true`，得到的就是第四轮那条路径 |
| P1-10 | **只推终态是规范允许的收窄，但收窄必须写在明处**：规范说「状态或产物变化时」，我们只在终态发。将来若出现 `input-required`（等人补输入），这个收窄就会变成「对面永远等不到那条通知」 | 现在没有 `input-required` 这个状态（`TERMINAL_STATES` 之外只有 `submitted` / `working`），所以收窄是安全的；写进 §3.6 与代码 docstring —— 将来加状态的人必须先读这两处 |
| P1-11 | **回调地址是调用方给的 = 一个 POST 原语** | 有意接受（内网部署下这就是用途），但它必须被**说出来**而不是被默认忽略：README 与 §3.6 都写明「它可以把我们指到任何 http(s) 地址」。技术兜底只做三件确定的事：只收 http(s)、不跟随重定向、响应只读 4 KiB。不做白名单，因为唯一真实用法（`localhost:8000/a2a/push`）会被白名单挡在外面 |

### 这一轮对八问的复答（只列有变化的三条）

- **二（磁盘即真源）**：回调配置**不落盘**，与任务表一致 —— 它属于一次运行里的一个 task，
  `tasks/get` 也拿不回来（重启后 `-32001`）。没有第二份拷贝。
- **六（极简）**：没有新增任何开关。没有 `--a2a-push` / `--a2a-no-push`：能力位在卡片里，
  收不收配置由协议决定，多一个开关就多一条要被解释的组合。
- **八（诚实）**：每一个「不会有第二次机会」「地址由对方决定」都写进了 README 与 §9，
  而不是留在代码注释里自我安慰。
