## 0. 结论先行

- **框架与哲学一致**：没有任何「根据内容决定模型怎么做」的判断被写进代码；
  删掉的东西比新增的多（删 SDK 依赖链、删 `max_retries` 旋钮、删 `model_dump` 分支）。
- **缺陷落在边缘机制，不在核心假设**：核心假设（「SDK 在这里的全部价值 = 一次 POST」）
  已被干净 venv 实测证实；失守的地方是三个副作用 —— **发版版本号**（P1）、
  **连接复用**（P1）、**目标场景的第二层障碍**（P1，本次未触碰）。

## 1. 设计哲学八问

1. **道（无硬编码智能）** —— 通过。
   `_retryable` 的状态码集合是 HTTP 语义事实，`_error_brief` 的取值顺序是协议约定，
   `_proxy_for` 读的是环境事实。没有一处「关键词过滤后替模型做决定」。

2. **一（世界观可写 · 可回滚）** —— 不适用。本次不碰 system prompt 入口。

3. **二（磁盘即真源）** —— 基本通过，留一个 P2。
   `post_chat()` 是 LLM 传输的唯一实现，无第二份拷贝。但项目里现在有两个
   HTTP 客户端：`channels/_http.py`（`urllib`）与 `llm.py`（`http.client`）。
   **这不是同一件事的重复**：频道要「用状态码表达业务结果」与长轮询，
   LLM 要「超时分离 + 代理隧道 + gzip」。强行合并只会加参数加到两者都难读。
   唯一真正重复的是「把错误正文压成一句话」，可抽取，P2。

4. **三（循环不预设）** —— 不适用。

5. **万物（自造）** —— 不适用，但见 P1-3：目标场景里模型的**动作**会被环境骗。

6. **极简** —— 净减少，但有新增。
   删：`openai` + 其依赖链（pydantic / pydantic-core / httpx / anyio / certifi→可选）、
   `max_retries` 字段（它只为钉住 SDK 的重试而存在，现在没有 SDK 就没有第二层）。
   增（三处，均有明确判据，不是「以防万一」）：
   - `_proxy_for()`：守一个原 SDK 有、直连替代会静默丢失的功能（见 P0-0/C-1）；
   - `certifi` 可选导入：iOS 上 OpenSSL 常找不到系统 CA，这是最可能的运行时失败；
   - `_ssl_context()` 缓存：一次重试就重复加载整份 CA bundle，手机上不值。

7. **成本** —— 见 P1-2：system 字节不变，但**每次调用失去连接复用**。

8. **诚实** —— 通过。`attempts` 如实报告真实 HTTP 次数；错误正文被带出来
   （`_error_brief`）而不是只报状态码；代理与超时分离各有测试守着。
   降权不靠措辞：删掉 `max_retries` 是**机制上**没有第二层重试，不是「我们约定了 0」。

### 2.3 我方案的硬伤

**P0（实现出来是错的）：无。**
判据：593 项 pytest 全过 + 干净 venv 真实往返 10 项全 PASS + 代理路径有白盒断言。

**P1-1 版本号与依赖已经不一致 —— 发版前必须处理（待确认）**
- 判据：`pyproject.toml:8` 与 `openthree/__init__.py` 仍是 `0.4.0`，而 0.4.0
  **已在 PyPI 发布且带 `openai>=1.0`**。同一版本号不可能对应两份不同的依赖。
- 改法：发新版本（建议 `0.5.0`），并同步 `docs/RELEASING.md:14`（版本行）、
  `:19`（依赖行仍写 openai，我**故意没改**：那行描述的是已发布的 0.4.0 快照）、
  `:18`（测试计数 582 → 593）。
- **为什么留给你拍板**：改版本号是发布决策，不该由我替你定。

**P1-2 失去 HTTP 连接复用（真实性能回退）**
- 判据：原来 httpx 有 keep-alive 连接池；现在每次 `chat()` 新建 TCP（HTTPS 还要
  TLS 握手）然后 `close()`。agent 每步一次调用 ⇒ 每步多一次握手。
- 为什么接受：一次握手（本机 ~10ms；移动网络 ~100-300ms）相对「模型生成几秒」
  可忽略；换来的是零第三方依赖 + 可移植到无编译器环境。
- 若要消除：加模块级连接缓存，但必须处理「服务端关了空闲连接导致下次请求失败」
  的重试逻辑 —— 那正是 httpx 替我们做的事，重新实现会显著加复杂度。

**P1-3 iOS 上的第二层障碍：`run_shell` 假设 Windows cmd（本次未触碰）**
- 判据：`builtins.py` 的 `run_shell` 文档与提示词里的环境事实都写着 cmd 语法
  （`set "X=1"`、无 `head`/`tail`、`&` 是顺序执行）。在 a-Shell 上是 sh。
- 影响：**pydantic 装不上的问题解决了，agent 仍会照 cmd 语法发命令**。
  这是目标场景里下一个会绊倒人的地方，明确列为未解决。

**P1-4 `docs/RELEASING.md:19` 依赖行仍是 openai**
- 见 P1-1：属 0.4.0 发布快照，发版时随版本号一起改，不单独改。

**P2 级**
- `_error_brief()` 与 `channels/_http.py:63` 的「错误正文截前 300 字」是同一件事，可抽取。
- 代理模式下明文 HTTP 目标用 `urlunsplit` 把整段（含 `?query`）塞进 path 参数，
  结果正确但写法脆弱，可改得更直白。
- `post_chat` 没有响应体大小上限（原 SDK 也没有，非回退）。
- `_ssl_context()` 缓存后，运行期改 `SSL_CERT_FILE` 之类的环境变量不会生效（进程内一次性）。
