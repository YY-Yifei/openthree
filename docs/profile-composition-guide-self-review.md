## 三、我的硬伤

### P0-1（已修）附录写了不存在的函数名

原稿写「`write_function` 的 `target` 校验 → `builtins.py`（`_resolve_target` 一带）」。
全包搜索：**`_resolve_target` 0 命中**。实际是 `write_function` 在 `builtins.py:630`，
拒绝逻辑与可写清单在 `:753`。

判据：文档里每个 `文件:行号` 都要能打开看到东西。改法：**改成实测到的行号**。

### P0-2（已修）继承了一条不存在的命令

上一版文档写「`python 文件.py --print-prompts` 能看到全文」。
全包搜索：**`--print-prompts` 0 命中**。真实入口是 `read_prompts()` 工具
（`builtins.py:1802-1812`）。

判据：命令必须自己跑过。改法：换成 `read_prompts()` + `logs/attached-prompts/<sha8>.md`。

### P1-1（已修）上一轮把 `-C ~` 记成了会展开

上一轮记录写「`~` 会展开【实测】」，本轮真跑发现：**只有 `-profile` 展开，`-C` 不展开**。
这一条若照抄进文档，读者会在自己目录里建出一个叫 `~` 的垃圾目录。

改法：§0.1 开头先点这个坑，§3.5 再对照说一次，§7 排错表列一行 —— 三处都点名。

### P1-2（已修）「不递归」是行为推断，不是代码里的判断

原稿写「不递归（代码 `workspace.py:1354`）」。全包搜「递归」**0 命中**。
真相是：profile 的定义里**没有**「再引用 profile」的机制（它只贡献 `functions/*.py`），
所以是结构上不可能，而不是某行代码在拦。

改法：措辞改成「它没有『再引用』的机制」，并删掉那个行号。

### P1-3（已修）两条提示文案只有结论、没有原文

「重复点名」「指到自己」原来只写了结论。本轮重测拿到原文并补进 §7：
